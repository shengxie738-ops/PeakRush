# FOLLOW.ART 桌面端高保真复刻：Codex Goal 实施方案

> **For agentic workers：**按本文件的任务顺序执行，每项任务有证据、实现和验收三个出口。使用环境中实际可调用的浏览器、终端及测试工具；不要仅因为文档提到某个插件就假定已经安装。
>
> **Goal：**以执行时冻结的 `https://follow.art/` 桌面端参考版本为唯一主要目标，重建其公开页面、排版、鼠标交互、滚动编排及 WebGL 视觉，并通过可复查的多视口截图、动态轨迹和功能测试持续缩小差异。
>
> **Architecture：**语义 DOM 承担内容与操作；独立 WebGL 层承担空间卡片、曲面界面等视觉；统一输入、时间和滚动进度；路由、资产、动效与验收数据分离。
>
> **Tech Stack：**空项目默认 Vue 3 + TypeScript + Vite + Vue Router；Three.js 实现 WebGL 重建；GSAP / ScrollTrigger 编排动效；仅在实测确有需要时启用 Lenis；Vitest + Playwright 验证。**这是复刻工程选型，不是对原站完整依赖清单的断言。**
>
> **Spec：**本文件第 1—16 节是设计与验收规格，第 17 节是执行任务，第 18—21 节是迭代、交付及来源。

**版本：**1.0  
**调研日期：**2026-09-29  
**目标网站：**https://follow.art/  
**交付范围：**电脑端网站，不开发移动端。  
**执行方式：**Codex Goal 模式；已有仓库优先沿用现有工程，不为追求技术栈一致而重写无关代码。

## 0. 开始执行前，先读这几条

### 0.1 真正要复刻的是什么

这项任务不是制作一个“具有 FOLLOW.ART 风格的艺术网站”，也不是给普通落地页加上几段淡入动画。目标是重建参考版本的**画面构图、字形比例、内容密度、空间关系、连续运动和可操作页面**。

优先级：

```text
参考版本正确
→ 关键字体与资产正确
→ 静态版式正确
→ 三维轮廓与透视正确
→ 滚动和鼠标时序正确
→ 路由与交互完整
→ 性能与边界稳定
→ 微小视觉差异收敛
```

“高级感”“Awwwards 风格”“看起来差不多”不是验收依据。原站没有的玻璃拟态、辉光、粒子、渐变球、炫光材质、通用 SaaS 卡片，都不能为了显得高级而加入。

### 0.2 本次研究的证据边界

本文件已经利用原站可读取的公开页面、原制作团队 Vide Infra 的项目页与技术案例，以及实现库的官方资料建立方案。**本次没有取得目标站的完整 DevTools 网络导出、可复现全站滚动录屏、生产 JavaScript 依赖清单或原始 3D 工程文件。**

因此，下列内容不能冒充已经测得：字体文件名、字号和颜色的精确 CSS 数值、相机参数、旋转周期、滚动锁定距离、着色器源码、模型文件名、GSAP/Three.js/Lenis 的原站使用情况及版本。

网页检索结果也可能来自缓存。**调研日期不等于网站截图冻结日期。**Codex 的任务 T00 必须创建本地参考证据，并以那一批证据锁定目标版本。遇到不同版本，不能把它们拼成一个“综合版本”。

### 0.3 全局约束

- 只做桌面端；主验收视口为 **1440 × 900 CSS px、DPR 1**，辅验收为 **1920 × 1080** 和 **1366 × 768**。另外做一次 1440 × 900、DPR 2 清晰度检查。
- 本地复刻包含公开页面和可演示交互，不包含真实社交平台后端、真实用户凭据收集、付费订阅或资金交易。
- 不向原站提交表单、发帖、点赞、注册、支付或其他写请求；只读观察。不能绕过登录、验证码、权限或访问限制。
- 不擅自购买字体、模型、服务或代理；不得将环境内字体文件作为交付物分发。字体权利不明确时，记录替代方案与可见误差。
- 优先利用获得授权的素材；公开可访问不等于拥有再分发权。对发布版本使用的品牌、肖像、作品、字体和截图分别记录授权状态。
- 不把整站截图作为最终网页，不用录屏代替应当交互的 WebGL，也不把页面全部画进 Canvas 来回避语义和功能。
- 保留 `prefers-reduced-motion`、键盘操作和 WebGL 失败后的可读降级；降级存在不代表视觉版验收通过。
- 不覆盖用户未提交修改，不执行破坏性 Git 清理，不修改无关功能；改动前先读项目 `AGENTS.md` 和已有脚本。

### 0.4 审查重点

|容易遗漏的输入或条件|必须表现出的行为|归属任务|
|---|---|---|
|进入页面后立即快速滚动，再反向滚动|不露空、不跳段，场景姿态与当前位置一致|T04、T07|
|图片或字体慢加载、窗口高度变化|排版重测后触发点更新，不残留旧坐标|T02、T04|
|曲面卡片转到背面或屏幕边缘|遮挡、裁剪、正反面符合参考，不镜像泄漏|T05、T06|
|从其他路由返回首页并重复二十次|不累积 Canvas、监听器、滚动锁或动画实例|T03、T10|
|浏览器没有可用 WebGL、降低动态效果、表单未填写|内容仍能访问；不伪装成原站真实服务|T09、T10|

```text
/goal 按 docs/FOLLOW_ART_Desktop_Codex_Goal_Clone_Plan_v1.0.md，完成 https://follow.art/ 的桌面端高保真复刻。先执行 T00 冻结当前参考版本和页面范围，再按任务逐项实现。覆盖冻结范围内的全部公开页面模板，重点重建排版、WebGL 名片空间结构、曲面产品展示、滚动连续性和鼠标交互。以三个桌面视口的参考对照图、至少 24 个关键静态状态、至少 10 条动态交互轨迹、全部 P0/P1 测试和最终差异报告验证。每轮只修复最重要的三个差异，保留最佳版本；未达标则继续有依据的下一轮。不得编造原站技术、资产或测量结果，不得把测试基线改成自己的当前输出来获得通过，不得接入原站写接口或真实支付。达到文档验收门槛后完成；若受工具、授权或预算阻塞，提交证据、已尝试路径、当前最佳结果和解除阻塞所需条件，不能宣称高保真完成。
```

### 1.2 Goal 与项目文件的关系

Goal 负责维持目标；仓库文件负责维持证据与状态。不要把整份方案复制进每一轮提示词。

每轮默认只读：

```text

quality/scorecard.json
当前任务规格 + 必要源码 + 当前参考截图
```

只有证据缺口或依赖接口变化时才扩大读取范围。不要每一轮重扫全仓库、重搜整个互联网或重读全部技术文档。

### 1.3 默认执行边界

用户已授权制作本地复刻。除需要真实账户、付费资产、扩大范围或不可逆操作外，不逐步重复询问是否继续。网络或浏览器不可用时，先尝试环境允许的另一条只读路径；仍不可用则完成可验证部分并记录阻塞，不能虚构浏览器观察。

## 2. 原站研究结论：事实、推断与工程选型分开

### 2.1 已获得的一手依据

|项目|结论|证据与限制|
|---|---|---|
|制作团队|Vide Infra 参与该项目的品牌、宣传站及产品设计开发|原站页脚与团队项目页相互印证。[S1][S7]|
|前端框架|制作团队说明使用 Vue.js|这是作者对项目版本的说明；不等于已检查当前每个部署包。[S8]|
|三维技术|制作团队明确说明使用 WebGL|作者特别指出主屏旋转人物名片及弯曲界面展示。[S8]|
|后端|制作团队说明使用 PHP 与 Symfony|本次仅重建前端体验，不需要照搬后端。[S8]|
|视觉方法|强烈的动态字体、饱和色彩、非传统字形处理、涂绘式细节|作者说明与项目展示图相符，不应误读为安静的画廊极简主义。[S7][S8]|
|页面范围|原站提供主页、介绍、产品、社区、价格、FAQ、账户入口及页脚页面|已发现具体链接；账户页面需浏览器运行后确认界面。[S1—S6][S18—S23]|

**没有确认：**原站使用 Nuxt、Three.js、GSAP、Lenis、Spline、React Three Fiber、Blender、Cinema 4D，或某种具体 CMS。它们不能出现在“已确认原站技术栈”中。

### 2.2 四类状态标签

后续所有调研记录使用以下标签，不混用：

- `MEASURED`：当前冻结版本，经浏览器、请求记录、计算样式或逐帧证据实测。
- `AUTHOR_CONFIRMED`：项目作者明确陈述，但未证明当前部署仍完全相同。
- `PROPOSED`：本方案建议的重建方法、工程预算或默认参数。
- `UNKNOWN`：尚无足够依据；必须有下一步验证动作，不能只留一个空泛待办。

例：

```json
{
  "claim": "首页卡片通过 WebGL 呈现",
  "status": "AUTHOR_CONFIRMED",
  "sourceId": "S8",
  "runtimeEvidence": null,
  "nextAction": "T00 捕获首页 Canvas、相关资源及初始和滚动后的关键帧"
}
```

### 2.3 当前版、历史版与未采用概念

制作团队同时展示了早期艺术品市场、后来的社交平台和未最终采用的视觉概念。[S7][S9]本次目标是用户指定 URL 的执行时公开版本。

必须遵守：

```text
当前参考站的浏览器证据
> 当前页面公开内容及资源
> 制作团队对已落地版本的说明
> 制作团队历史案例展示
> 第三方画廊标签或自动生成分析
```

案例中的笔记本或平板外框是展示载体时，不把外框误做成网站自身 UI。历史概念中的经典绘画、旧宣传语或旧栏目，不因截图好看就加入当前版。

### 2.4 这意味着怎样的复刻策略

本项目的主要难点是**二维排版与三维页面视觉之间的精确协作**，不是建设一个复杂的自由漫游三维世界。

默认重建路线：

```text
HTML/CSS 排版
+ 纹理化名片与产品界面
+ 可弯曲的程序化网格
+ 统一滚动/时间/鼠标输入
+ 可对照的关键帧配置
```

这个路线是工程选择。是否需要额外 GLB、复杂光照或视频，必须由资产与画面证据决定。

## 3. 页面范围：不能只做首页第一屏

下表表示发现了链接或页面内容，不表示已经完成各页面的浏览器视觉审计。

|路由|重建范围|实现要求|
|---|---|---|
|`/`|完整营销首页|全部实际章节、滚动过渡、三维视觉、导航与页脚|
|`/about`|故事、团队和合作信息页面|排版、照片、章节间距与页面独有视觉|

|`/faq`|多主题常见问题|分类、展开规则、锚点和长内容排版|
|`/community-board`|公开社区列表|卡片布局、分页/加载更多及实际可见筛选|
|`/signin`|登录入口|浏览器核验后重建界面；只使用本地演示逻辑|

|`/privacy-policy`|文本模板|与上项同模板，内容不以营销文案替代|
|`/cookies-policy`|文本模板|与上项同模板，Cookie 控件行为单独验证|

来源：[S1—S6][S18—S23]。

### 3.2 需要探索后决定的页面

制作团队案例还介绍人物目录、个人名片、作品和资讯等平台界面。[S7]T00 必须点击**当前页面真实链接**确认它们是否仍公开可达。

对实际发现的页面执行以下规则：

- 同源、无需登录、从主流程可达的新模板：纳入完整模板复刻。
- 重复模板的海量人物或帖子：每种模板选 2—3 个授权或演示实例，不批量复制数据库。
- 登录才能访问：标记 `AUTH_BLOCKED`，不得根据历史截图声称还原了当前账户内界面。
- 外链、社交平台、外部支付和品牌包：只重建入口，不克隆外站。
- `404`：提供本地可用的错误页；只有存在当前参考证据才宣称与原站错误页一致。

T00 输出 `route-map.json`，将“所有公开页面”转成有限、可审计的模板范围。不得默默缩小为单页。

### 3.3 本地交互与真实业务的边界

默认提供演示账户状态、前端表单校验、筛选、切换、展开和内容加载。演示状态必须在本地有清晰标识；不发送凭据、不真实付款、不真的联系站点人员。

演示数据库使用确定性、非敏感数据。模仿布局不要求复制真实用户的全部资料、帖子和作品。缺少版权或内容权限的区域，使用在比例、色彩和密度上匹配的替代素材，并在差异报告中列出，不隐瞒替换。

## 4. T00 必须完成的浏览器取证规格

### 4.1 固定环境与参考版本

生成 `evidence/reference-lock.json`：

```json
{
  "schemaVersion": 1,
  "targetOrigin": "https://follow.art",
  "capturedAt": null,
  "browser": null,
  "os": null,
  "primaryViewport": { "width": 1440, "height": 900, "dpr": 1 },
  "zoom": 1,
  "locale": "en",
  "cookieState": "record-on-capture",
  "reducedMotion": false,
  "routeMapFile": "evidence/route-map.json",
  "notes": ["初始模板；T00 写入实际采集值后才能标记参考锁定"]
}
```

系统缩放与浏览器缩放分开记录；参考和本地保持浏览器、操作系统及 DPR 一致。不要把操作系统字体栅格化误差当作布局误差。

### 4.2 采集顺序

先完成首页和导航全链路，再深入子页；只抓已发现的相关资源，不对服务器进行无界爬取。

1. 新建无登录浏览器上下文，记录首访 Cookie 提示和加载过程。
2. 获取初始 DOM、实际链接、Canvas/Video 元素、可见字体与关键节点计算样式。
3. 等待关键字体、首屏图像解码和初始画面稳定；不是盲目等待固定两秒。
4. 捕获首屏，再做完整慢速下滚和反向上滚录屏。
5. 对每个主要视觉章节捕获进入前、进入、中心、退出和交界状态。
6. 单独测试悬停、拖动、点击、计费切换、FAQ、路由返回及窗口变化。
7. 对每个公开模板记录首屏、正文和页脚；对子页独有交互额外录制。
8. 保存原始图片、视频和元数据，随后建立参考锁，不再以本地产物覆盖。

### 4.3 动态取证不能只留一张全页长图

至少记录下列十条交互轨迹，内容以当前站真实行为为准：

|轨迹 ID|输入动作|要回答的问题|
|---|---|---|
|D01|首页先不操作停留 8 秒，必要时延长至完整周期|是否自动旋转？速度、周期与方向是什么？|
|D02|鼠标从左至右，再移出 Hero|鼠标影响相机、对象、字形、笔触，还是没有影响？|
|D03|首页慢速下滚全程|哪些对象跟滚动连续变化，哪些只在进入时播放？|
|D04|同一路径反向上滚|是否可逆？有无一次性动画或状态滞后？|
|D05|连续大幅滚轮输入后停下|惯性和动效何时收敛？会不会跳过关键状态？|
|D06|主导航、主 CTA、人物/产品区域 hover|涂绘、变色、字形和光标的实际变化|
|D07|进入子页再返回首页|路由过渡、滚动恢复和重入动画规则|
|D08|价格三个周期依次切换|价格、说明、选中态和高度如何联动？|
|D09|FAQ 连续展开/关闭两项|单开还是多开？滚动位置是否调整？|
|D10|1366×768 与 1920×1080 之间 resize|字形换行、卡片裁剪、触发点如何改变？|

若原站确有拖动、视频弹层或特殊菜单，把对应轨迹加到 D11 以后；没有证据不能自行加入。

### 4.4 捕获与测量字段

每个参考状态至少记录：

```text
stateId / route / captureTimestamp / viewport / dpr
cookieState / hoverTarget / focusTarget
scrollY / scrollDirection / sectionId / sectionLocalProgress
elapsedFromSceneReadyMs / animationPhaseDescription
fontReady / criticalImagesReady / mediaState
screenshotPath / videoPath / importantRects / confidence
```

首屏加载阶段另外记录未完成资产加载的状态。用于稳定画面对比时，不把加载失败、字体未到位或 Cookie 遮罩误当成最终设计。

### 4.5 网络与技术证据

浏览器可用时，采集首访和一次完整滚动的请求元数据。文件优先保存为**去敏的资源清单**；原始 HAR 如含 Cookie、令牌、邮件或账户资料，禁止进入公开仓库。

重点检索：

```text
.js .css .woff .woff2
.svg .png .jpg .jpeg .webp .avif
.glb .gltf .bin .ktx2 .hdr .exr
.mp4 .webm .m3u8 .json
```

记录 URL、响应类型、状态码、字节数、调用时机与归属场景。响应类型比文件后缀更可靠；无后缀资源也要分类。

框架与依赖判定必须有来源：框架特征、公开源代码、构建包中的明确版本标记、实际模块或官方声明。单纯“有 Canvas”“滚动很顺”“HTML 有某个词”都不能证明某个特定库。

### 4.6 工具受阻时的可接受替代

优先尝试另一种允许的只读浏览器方式；其次利用用户提供的同版本录屏/截图或制作团队公开演示补充**历史视觉机制**。来源级别必须随之降低。

不能访问当前页面时，可以实现已确认的静态模板与可独立验证的三维机制，但不进入“当前全站高保真验收已通过”状态。不把访问失败解释成“页面不存在”或“网站没有动画”。

## 5. 资产体系：先弄清 3D 来自哪里

### 5.1 三维观感不等于存在模型文件

旋转名片、弯曲产品截图和文字变形都可能由程序化几何与纹理完成。**本次没有确认任何原站 GLB、FBX、Blender 或 Cinema 4D 文件。**不要让任务变成“找不到模型，所以随便生成一个”。

|资产类型|需要获取的信息|建议重建方式|优先级|
|---|---|---|---|
|品牌字标和标题字形|原始 SVG/文字实现、点号位置、拉伸规则|授权矢量或真实字体 + 精确布局|P0|
|标题字体、正文字体|实际 family、字重、文件、轴值、许可|合法字体；替代必须报告度量差|P0|
|人物名片面|宽高比、头像、文字区、作品缩略图、正反面|高分辨率纹理或静态生成纹理|P0|
|产品界面展示图|原始图像、裁剪、浏览器框是否在图内|纹理 + 曲面网格|P0|
|画笔、箭头、涂绘符号|真实路径、笔缘、透明度、覆盖顺序|SVG / Alpha 纹理 + mask|P1|
|团队和作品图像|比例、色调、焦点、授权|本地授权资源或匹配替代|P1|
|视频或序列|编码、尺寸、时长、播放/滚动控制方式|有证据才采用对应播放器或序列|条件性|
|真实三维模型|URL、拓扑、材质、贴图、许可|有证据才引入模型加载器|条件性|

字段里的 `null` 是待采集状态，不能在最终资产验收时继续存在于核心资源中。对于没有源 URL 的程序化资产，写明 `kind: procedural`、生成源码路径和参数配置；不能伪造一个远程文件名。

### 5.3 文件组织与权利状态

```text

```

`rights` 使用 `owned`、`licensed`、`permission-required`、`unverified`。禁止把 `publicly-accessible` 当成许可。私有研究参考与最终发布资源分目录；公开仓库不打包许可不明的原站字体、人物照片或作品。

### 5.4 字体测量的优先级高于加动画

必须量出：大写字高、每个主标题的总宽、字间距、行高、笔画粗细、显示区域裁剪和断行。对于刻意拉伸的标题，还要记录横纵比和变形锚点。

建议流程：

```text
原站 computed style 与字体加载记录
→ 相同文本的字形度量
→ 原始比例与静态 transform 分离
→ 动画前后比例分别测量
→ 检查字体是否加载后仍发生一次排版变化
```

不能默认用 Inter、Arial 或任意窄体替代后再靠 `scaleX` 强行对齐。目标字体缺失时，先找合法替代并测差；形状差异属于视觉阻塞，而不是可以被隐藏的实现细节。

### 5.5 不需要的资产与成本

默认不引入高多边形雕塑、环境 HDR、角色骨骼或物理碰撞库。若只是无光照的平面 UI 纹理，加入重型 PBR、景深和泛光会增加成本，并可能改变原站的平面印刷感。

## 6. 视觉系统与首页拆解

### 6.1 视觉还原的核心

设计团队的项目资料展示了橙色、黑色与浅色区域之间的强反差，巨大窄长字形与涂绘细节，以及空间化的界面展示。[S7][S8]以下是本方案据此提出的还原重点，具体值必须由当前版本测量：

- 色块要作为整段叙事的背景或结构，不把橙色降格为一个普通按钮强调色。
- 大标题与图像、三维卡片之间的遮挡关系，要像构图的一部分，而不是独立堆叠组件。
- 标题的可见外框、裁切和字面面积比“CSS font-size 看起来很大”更重要。
- 小字号信息、细线、空白区和按钮对齐，负责把强表现画面约束在清晰的版式中。

不要从单张案例图取几个 HEX 值后宣称已掌握设计系统。案例视频缩略图、压缩图片和当前 CSS 的颜色可能不同。

### 6.2 设计 Token 不预填伪精确值

在 `design/tokens.reference.json` 记录：

```text
颜色：主背景 / 深色区域 / 浅色区域 / 正文 / 细线 / hover
字体：display / body / accent 的 family、weight、stretch、variation
排版：标题字面高、行高、字距、宽度、断行
几何：左右边距、列线、导航高、按钮尺寸、边框
图像：比例、object-position、圆角、裁切区域
视觉层：DOM、Canvas、涂绘、导航、模态层的遮挡顺序
```

每个值关联 `evidenceId`、单位和置信等级。工程初始化可临时使用默认值，但不能把默认值写回参考 Token。

### 6.3 首页章节映射

原站当前可读取内容包含以下主题；文字读取顺序不自动等同于精确视觉分屏或动效边界。[S1]

|建议章节 ID|内容线索|主要还原对象|优先检查|
|---|---|---|---|
|`home.hero`|品牌与数字名片主张|巨大字形、名片空间场景、首屏构图|首屏是否有自动动画、字形是否响应指针|
|`home.how`|使用说明|过渡版面、图像与短句层级|是否与上一场景共享对象或 Canvas|
|`home.audience`|服务的创作者群体|标题、列表和背景切换|是否为普通流式排版而非锁屏|
|`home.testimonials`|成员评价|评价内容、图片、切换或播放入口|不能只留下一个空标题|
|`home.centralize`|集中展示与四项能力|分裂/巨大标题、编号、说明与展示图|编号是否随进度变为 active|

### 6.4 推荐的逐层实现顺序

每个章节都经过五次独立比对：

```text
1. 只显示版面边界与字块：检查位置、占比和空白。
2. 使用正确字体与内容：检查断行、可见字高和基线。
3. 加入真实比例资产：检查颜色与图像焦点。
4. 在某一冻结状态加入三维：检查透视、轮廓、遮挡。
5. 连起来运行：检查速度、触发点、连续性与可逆性。
```

在第 2 步还错得明显时，不花时间调整第 5 步的缓动曲线。

## 8. 统一运行时：不要让滚动、动画和三维各跑一套

### 8.1 数据流

```text
原生滚动 / 可选 Lenis      鼠标指针       路由与资源状态
          \                  |                 /
                  Motion Runtime
                         |
             FrameInput + 章节局部进度
                  /                  \
         DOM / GSAP 时间线       WebGL 场景状态
                  \                  /
                 同一状态的最终画面
```

建议接口：

```ts
export type SectionId = string;

export interface FrameInput {
  timeSec: number;
  deltaSec: number;
  scrollYPx: number;
  velocityPxPerSec: number;
  pointerNdc: { x: number; y: number };
  viewport: { width: number; height: number; dpr: number };
  reducedMotion: boolean;
}

export interface SceneController {
  id: SectionId;
  update(frame: FrameInput, progress: number): void;
  resize(width: number, height: number, dpr: number): void;
  dispose(): void;
}
```

`progress` 只表示章节推进，不包含无限循环的自转相位。需要时间循环的场景，另外使用 `timeSec` 与冻结的初始相位。

### 8.2 唯一时钟与单位

默认使用一个 GSAP ticker 调度应用自己的帧工作；可选 Lenis 手动接入，关闭它的自动 rAF。GSAP 与 Lenis 的时间单位转换以官方集成为准。[S12]

执行顺序固定为：

```text
更新平滑滚动 → 更新章节进度 → 计算场景姿态
→ 更新 DOM/三维属性 → 渲染 WebGL → 采样调试指标
```

不要同时启动自写 rAF、Lenis autoRaf 和独立 Three.js 动画循环。第三方播放器有自己的内部时钟不算错误，但不能让它同时控制同一场景的进度。

### 8.3 惯性不能叠三层

若已用 Lenis 平滑实际滚动，再给 ScrollTrigger 设置较长的 scrub 追赶，再在 WebGL 对进度二次插值，画面会明显落后。默认只让一层决定主滚动跟随，额外平滑仅用于实测确有弹性的小范围对象。

指针缓动采用与帧率无关的衰减：

```text
alpha = 1 - exp(-lambda × deltaSec)
current = current + (target - current) × alpha
```

这里的 `lambda` 是重建参数，不是原站测量结果。通过目标录屏的停稳时间反推，而非凭喜好选一个很慢的值。

### 8.4 生命周期与路由

进入路由后等待必要 DOM 和资产就绪，再创建章节时间线；离开路由时只清理该路由拥有的 timeline、ScrollTrigger、监听器、场景和资源引用。不要用全局 `killAll()` 顺手破坏其他组件。

字体或图像导致布局改变后，合并重测并 refresh；resize 做节流；不要每帧读取所有节点的 `getBoundingClientRect()`，也不要边读边写造成强制布局。

默认缓存文档坐标，再根据实际滚动推导视口坐标。固定或已变换元素单独管理，不套用错误的普通文档流公式。

### 8.5 Vue 与 WebGL 状态隔离

几何、材质、纹理和 renderer 不放进大型深层响应式对象。使用普通对象、必要的浅层引用，业务层只接收低频状态。Vue 官方提供了浅层响应性等性能工具；这里的选择是避免渲染循环引发无意义的组件更新。[S17]

## 9. 重点一：空间名片与旋转卡片组

### 9.1 先判断结构，不先寻找模型

制作团队确认了旋转名片与 WebGL 的关系。[S8]但是，当前站的名片数量、环形结构、弯曲程度、入场方式和运动轴仍需 T00 核验。以下是**用于拟合参考图的程序化重建方案**，不是原站源码还原。

把场景拆成四层：

```text
场景相机与投影
└── 卡片组整体姿态：位置、倾斜、旋转
    └── 单卡位置与朝向：角度、间距、前后遮挡
        └── 单卡表面：曲率、圆角、纹理、正反面
```

这样能分别调节整体构图、卡片排列和表面弯曲，避免把所有差异都塞进一个无法解释的 CSS transform。

若实测是旋转圆环，可用以下基准布局；若不是，保留模块边界，替换布局函数，不能让假设反过来覆盖参考。

```text
theta_i = theta0 + 2π × i / N + phase(time, progress)
center_i = (radius × sin(theta_i), height, radius × cos(theta_i))
outwardNormal_i = (sin(theta_i), 0, cos(theta_i))
```

以默认法线为 +Z 的卡片平面为例，单卡绕 Y 轴旋转 `theta_i`，再叠加整个卡片组的倾斜。相位拆成连续时间项和章节进度项；禁止让滚轮每触发一次就累计一个不可逆旋转量。

### 9.2 单卡的圆柱弯曲

普通刚性平面可以验证空间位置，但不一定能重建参考的表面形状。先用细分平面做圆柱弯曲，不默认引入流体噪声。

设局部横坐标为 `x`，曲率为 `k`，一种重建公式为：

```text
x' = sin(k × x) / k
y' = y
z' = z + (1 - cos(k × x)) / k
```

`k` 接近零时应连续回到平面，不能产生除零：

```text
x' ≈ x - k² × x³ / 6
z' ≈ z + k × x² / 2
```

这只是一个可解释的起点。弯曲方向、曲率中心、卡片宽度及是否沿另一个轴弯曲，均由多帧参考确定。保留原始顶点数据，不能每一帧对已经变形的顶点再次变形。

**初始网格预算建议：**横向 32—64 段，纵向根据变形需要选择 1—24 段。它不是原站配置；先在最大显示尺寸检查轮廓是否分段，再增加细分。Three.js 的平面分段与自定义着色器可承担这类重建。[S15][S24]

### 9.3 拟合顺序与可辨识性

按下面顺序校准，冻结前一组后再进入下一组：

1. 卡片真实宽高比、可见数量和基本排布。
2. 全组屏幕边界、中心、占屏比例和被裁切部分。
3. 相机透视强度与前后尺寸变化。
4. 单卡曲率、法线朝向、遮挡顺序和组倾斜。
5. 初始相位、循环周期、滚动关联和鼠标响应。

不能只拿一张正面图同时拟合半径、焦距和整体缩放：多种组合都能近似同一张图，却会在转动后明显不同。至少使用正面、侧面、背面及过渡中间态检查。

每次记录 `camera / ring / card / texture / motion` 五组参数的差异，而不是“调了一点透视”。

### 9.4 正反面、透明边缘与深度

逐项检查：

- 背面是另一个设计、纯色，还是正面反向可见？不能默认 `DoubleSide` 解决一切。
- 正面文字在背面是否不该出现？需要时分别构建前后表面，避免镜像文字。
- 卡片交叉时深度遮挡是否正确？不要为修透明排序而把所有深度写入关闭。
- 圆角是几何轮廓、纹理透明区域还是 shader 遮罩？沿用最接近参考且可稳定抗锯齿的方法。
- 卡片边缘是否真有厚度？没有证据就不加金属倒角、玻璃反射或发光边。

透明卡片排序问题，先减少不必要的半透明面；硬边圆角可以评估 alpha test 或明确的表面分离。具体材质和阈值必须经过截图，不能把某个通用配方当成原站答案。

### 9.5 纹理、文字与颜色

卡片纹理优先使用有授权的实际设计。只能重建时，使用确定性的离屏 Canvas 生成小范围卡面，必须等字体加载完成后再绘制；不得每帧截图 DOM 或每帧上传整张纹理。

生成纹理需要记录：尺寸、字体来源、内容版本、像素密度、边距和透明区域。视口变化不意味着无条件重绘全部纹理，只有目标分辨率档位改变时才重建。

图片等颜色纹理与渲染输出必须使用一致的颜色管理；数据纹理不能当作颜色纹理。Three.js 官方明确区分线性工作空间、输入颜色空间和输出转换。[S13]

如果参考是平面图形质感，优先从不受灯光影响的材质开始。不要默认加入环境贴图、金属度、强 tone mapping 或 bloom，导致原本精确的橙色、黑色与图片肤色发生变化。使用自定义 shader 时检查输出转换路径，避免重复 gamma 转换。

### 9.6 Shader 变形的隐藏风险

GPU 顶点变形不会自动修正所有 CPU 侧空间判断。必须检查：

- 变形后的可见范围是否超出原始包围盒，导致边缘突然被裁掉。
- 点击使用的射线是否仍按未变形平面命中。
- 需要光照时法线是否跟随变形；没有光照需求就不要引入不必要的法线复杂度。
- 多场景复用纹理时，某个组件卸载是否误释放其他组件仍在使用的资源。

解决顺序是：正确估计边界与命中映射；只有对象数量很小且经过测试时，才选择局部关闭视锥裁剪或用可靠的二维交互映射。不能全场景关闭所有优化掩盖错误。

### 9.7 核心测试

至少覆盖：零曲率连续性、正负曲率镜像关系、固定输入得到相同姿态、正反向滚动可回到同一状态、侧面及背面无文字泄漏、离开路由后资源引用归零。

几何公式的单元测试通过，仅证明公式实现符合定义；还必须通过参考截图确认形状符合原站。

## 10. 重点二：曲面产品展示与 DOM / WebGL 对齐

### 10.1 不把产品展示降级成普通截图卡片

产品界面弯曲展示是制作团队明确描述的视觉方法。[S8]重建时，将其视为“界面内容 + 有形变的展示表面 + 相机 + 章节运动”的组合，而不是给一张图片加 `rotateY()` 就结束。

默认采用：

```text
经过核验的产品界面纹理
→ 细分矩形平面
→ 横向或纵向曲率
→ 局部旋转 / 平移 / 缩放
→ 与该章节的滚动区间绑定
```

曲率模型优先简单可解释。只有参考明确出现非圆柱曲面、波动或折叠，再增加更复杂的顶点函数。产品内容必须清晰可辨，不能用高模糊截图掩盖资产不匹配。

### 10.2 保留 DOM 布局占位

让 DOM 元素承担章节的实际尺寸和文档流，WebGL 只覆盖视觉。

- 占位宽高使用确定比例，图片加载前后不得改变整页结构。
- WebGL 就绪前显示静态 fallback；第一帧成功渲染后再切换，避免空白。
- 切换后不能同时露出底层平面图和上层曲面，形成重影。
- 点击区域仍应能通过语义链接或明确的命中层操作。
- `opacity: 0` 的 DOM 仍可能接收事件，需要明确事件归属。

不把整个章节 `display: none` 后再尝试用原来的尺寸对齐 Canvas。

### 10.3 投影与坐标转换

所有排版测量使用 CSS 像素；Canvas drawing buffer 使用物理像素。DPR 只改变采样分辨率，不应把物体尺寸再放大一次。

对于距离相机 `d`、与相机成像平面平行的参考平面，其可见高度为：

```text
visibleHeight = 2 × d × tan(verticalFov / 2)
visibleWidth = visibleHeight × viewportAspect
```

DOM 中心 `(cx, cy)` 对应：

```text
ndcX = 2 × cx / viewportWidth - 1
ndcY = 1 - 2 × cy / viewportHeight
```

以上关系只能直接用于设定好的参考平面。曲面顶点有深度变化或相机发生旋转时，要通过投影矩阵与 unproject / ray-plane intersection 求解，不能继续假设所有像素拥有同一个缩放因子。

### 10.4 多场景的渲染组织

默认以路由为单位共享 renderer。多个独立 DOM 区域需要 Canvas 时，评估一个 renderer 配合区域裁剪和场景注册表，避免每个章节都创建一个昂贵的 WebGL 上下文。

但共享并不是无条件要求：一个巨大的固定 Canvas 也会增加滚动层、裁剪和透明叠加复杂度。T00 确定实际展示结构后，在“首页共享 Canvas”与“少量独立 Canvas”之间做一次明确决策，并记录原因。

必须处理：

- 元素完全离开视口后停止无意义绘制。
- `scissor` 与 viewport 的 Y 轴方向差异。
- 固定导航、弹窗和 Cookie 层的层级。
- 滚动容器、`overflow: hidden` 和被 transform 的父元素。
- 切换页面时取消旧的裁剪区，不残留上一页的画面。

### 10.5 曲面接缝验收

针对每个产品展示，在章节进入、正中、退出和反向返回时截图。重点检查：四角位置、曲率轮廓、文字锐度、图像裁切、DOM 与 Canvas 接缝、背景颜色以及层级关系。

如果只在某个视口正确，先修坐标与投影模型，不新增针对每个截图的独立 magic number。

## 11. 重点三：动态排版、笔刷反馈与章节过渡

### 11.1 字体是构图，不是最后换上的皮肤

先通过计算样式与实际字体请求确定字体、字重、伸缩与字距。未确认授权或文件之前，不将第三方字体推荐当成事实。

标题逐项建立排版基线：

```text
字体与字形 → 字重 → 宽度 / 伸缩 → 字号 → 行高
→ 字距 → 换行 → 文字框边界 → 与图形的叠压关系
```

不能用大量 `scaleX()` 修补完全不同的字形，然后宣布字体一致。字体替代不可避免时，将误差记录为资产阻塞，而不是无限微调布局。

语义文本保留为真实 HTML。拆字动画中的视觉副本设为 `aria-hidden`，辅助技术读取一个完整标题，不能让屏幕阅读器逐个朗读重复字符。

### 11.2 区分几种看似相近的字形运动

T00 需要判定标题变形属于哪一种：

|参考现象|优先重建方向|不能直接假定|
|---|---|---|
|整行横向压缩或放大|容器或文字变换、必要的布局补偿|不一定是 variable font|
|单字错位、旋转或局部拉伸|分字 span 和局部 transform|不一定需要 WebGL 文本|
|字面连续弯曲或像素级形变|授权字体纹理 + shader，或可验证的矢量变形|不能用简单淡入代替|
|字宽改变但笔画特征保持|检查真实 variable font 轴|不能仅凭视觉断定轴名|

把参考中没有出现的“液体字”“磁吸大幅变形”删掉。运动的幅度、方向和停稳状态比选择哪一个库更重要。

### 11.3 笔刷式 hover

制作团队将笔刷式反馈作为视觉语言之一。[S8]具体哪些元素使用、笔画如何出现，要逐个观察。

实现候选包括 SVG mask、`clip-path`、路径描边动画和图形层横向显现。选择能保持原参考笔触边缘的方式，不能统一替换成一条细直线。

对于每一种可交互组件，保存：

```text
default / pointer-enter / hold / pointer-leave / keyboard-focus / disabled
```

鼠标离开时必须从当前进度自然反向或退出；快速进出不能堆积多条 timeline。键盘 focus 采用可见的等价反馈，不让可用性取决于鼠标。

### 11.4 类翻页、遮挡与进入退出

“像翻阅册页”的描述是创意方向，不等于每个章节都需要三维翻页。[S8]先判断当前页面实际采用的是遮罩、层叠、背景切换、固定章节、整体旋转还是普通滚动。

对重叠章节分别确定：

- 哪个元素留在文档流，哪个被固定。
- 固定从什么可观察边界开始、何时结束。
- 下一层从上方、下方还是裁剪区域进入。
- 背景切换是硬切、颜色插值还是遮挡结果。
- 上下滚动时过程是否对称。

不能给所有 section 添加长 `pin`，把本来紧凑的页面拉成长篇演示。固定距离是拟合参数，必须来自参考滚动证据。

### 11.5 自定义鼠标不是必做项

只有参考确有自定义光标、磁吸、跟随图形或拖拽反馈，才实现对应功能。不得为了“创意站必备”隐藏系统光标或添加巨大的鼠标圆环。

## 12. 动效编排：从描述变成可测量的状态函数

### 12.1 统一的章节动效规格

在 `src/motion/motion.config.ts` 中记录每个动效的参数与证据引用。配置至少包含：

```ts
export interface MotionSpec {
  id: string;
  sectionId: string;
  driver: 'scroll' | 'time' | 'pointer' | 'event';
  referenceStateIds: string[];
  startRule: string;
  endRule: string;
  channels: Array<{
    target: string;
    property: string;
    keys: Array<{ at: number; value: number; ease?: string }>;
  }>;
}
```

这里的 `at`：滚动驱动为归一化章节进度，时间驱动为秒，指针驱动为已声明的归一化坐标；不得在同一通道混用。`startRule`、`endRule` 必须写清可测量的触发边界，不能只填“进入时”“结束时”。

### 12.2 先量滚动距离，再量运动

依次记录页面总高度、章节起止坐标、视口尺寸、固定元素、实际滚动位置，以及动画进度。不要只记“页面滚到 40%”。字体或窗口变化会让全页百分比对应完全不同的章节。

推荐在每个重点章节采样局部 `p = 0 / 0.25 / 0.5 / 0.75 / 1`。这些数值是**采样方案**，不代表原站原始关键帧。若视觉变化集中在某一小段，则增加该段采样密度。

对 ScrollTrigger 的 pin、scrub、refresh 采用官方生命周期和接口，不复制未经验证的旧版配置。[S11]

### 12.3 必须分开拟合的两个问题

**输入响应拟合：**相同滚轮 / 触控板输入后，实际页面滚动多久、移动多少、何时停稳。

**姿态拟合：**当实际滚动位置相同时，卡片、标题和遮罩应该处于什么状态。

先解决姿态，再解决输入响应。否则会把平滑滚动造成的时间差误认为三维几何错误。录屏对比既保留输入时间戳，也保留实际 scrollY，不只比较两段视频的同一播放时间。

### 12.4 初始动画与连续循环

入场动画、持续自转和滚动变形必须能独立控制：

```text
最终姿态 = 初始布局 + 入场贡献 + 持续相位贡献 + 滚动贡献 + 鼠标微调
```

这是概念分解，不意味着数值一定线性相加；旋转组合应按固定变换顺序或四元数处理。顺序一旦确定，写入测试，不允许不同组件各自变更。

刷新页面、从其他路由返回和直接打开深层链接，需要明确初始状态。不得依赖“之前已经看过 Hero”才能正确显示。

### 12.5 反向与跨段跳转

通过绝对输入计算姿态，而不是靠“上一段动画已经播放过”递推。重点验证：

- 直接跳到页尾再向上滚。
- 快速跨过整个 pin 区。
- 在章节边界小幅反复滚动。
- 点击锚点后马上反向滚动。
- 页面 resize 时停在章节中间。

上述输入都应该得到合法状态；没有参考证据时可以选择合理的稳定行为，但必须标为复刻补充行为，而不是原站实测。

## 13. 其他页面的具体实现要求

### 13.1 页面不是共享首页模板的替换文案

`AboutPage`、`ProductPage`、`PricingPage` 等需要自己的页面宽度、标题构图、首屏节奏和内容网格。只共享实际相同的导航、页脚、按钮和基础排版令牌，不把每个页面强行统一成一个通用组件模板。

### 13.2 功能与视觉矩阵

|页面 / 模块|必须实现|重点视觉证据|本地边界|
|---|---|---|---|
|About|故事章节、人物区和合作内容|文字与照片比例、图像裁切、长页节奏|不虚构团队履历；可使用明确标注的演示内容|
|Our Product|产品介绍、步骤、应用场景与 CTA|产品纹理、曲面姿态、跨章节关联|账户相关 CTA 指向本地演示入口|
|Pricing|计费周期切换、卡片状态、权益呈现|选中态、旧价/优惠价层级、禁用或勾选差异|不发起真实订阅|
|FAQ|分类、问题展开收起、长答案|分组标题、分隔线、展开后的排版|按实测决定单开或多开，不擅自统一|
|Community Board|列表、公开可见控件、加载更多|卡片密度、作者区、媒体裁切和分页位置|使用确定性 fixture，不批量复制用户数据|
|Sign in / Sign up|真实可见步骤、校验、密码显示与错误态|表单尺寸、品牌层、焦点和帮助信息|清楚标注演示；不得发送真实凭据|
|Gift card|公开展示、选项与按钮状态|卡面、价格区、背景和购买入口|动作止于本地演示反馈|
|Legal|同类文本模板、标题、锚点与页脚|阅读宽度、行距、段落间距|不宣称原站法律条款适用于本地项目|
|Global|导航、Cookie 层、页脚、路由返回|跨页位置和状态一致|Cookie 不设置真实追踪服务|

页面内容依据当前公开页面核验。[S2—S6][S18—S23]登录与注册入口的文本抓取不足以显示界面，T00 必须实际运行页面后再拆分组件。

### 13.3 价格、权益与动态内容

价格统一由 `content/pricing.ts` 中的冻结数据驱动，显示金额、周期、折算单位和优惠标识不能散落在多个组件里。参考采样日期与货币一起记录。

**特别注意：**网页纯文本中出现某项权益，不能证明 Free 方案包含该权益；它可能在视觉上被划掉、置灰或显示不支持图标。必须查看视觉状态，再写数据结构。

不要让“动态原站今天换了一个帖子”成为整个测试每天失效的原因。动态正文采用固定测试实例，但布局、密度、图像比例和字体不能通过随意缩短内容来作弊。至少保留长标题、无图、横图、竖图和多行作者信息等边界样本。

### 13.4 账户界面的防混淆

复刻用于本地演示，账户页面在非参考截图模式下保留明确的演示提示。视觉测试可固定提示的位置，并将其作为批准的偏差，不允许为了像原站而隐藏实际服务性质。

提交时只在本地校验并返回模拟结果；不得存储密码，控制台和日志也不记录输入内容。用户意外填入真实密码时，不能发送到任何远程地址。

## 14. 证据驱动的视觉与动态测试

### 14.1 两套基线必须分开

```text
evidence/reference/   原站冻结参考；只读且有哈希

evidence/local/       本地当前实现；每轮生成

evidence/diffs/       叠图、局部差异及测量结果

tests/visual/         本地获准版本的回归快照
```

Playwright 的视觉比较可用于稳定的截图回归，但“本地快照测试通过”不等于“和原站相同”。官方也要求关注操作系统、浏览器和环境差异。[S16]

绝对禁止通过更新本地 snapshot，把当前错误画面变成新真值；也不能把本地截图复制到 `reference/`。参考更新必须有新一轮人工可审查的版本冻结说明。

### 14.2 固定环境，不冻结目标的关键特征

静态截图固定：浏览器版本、系统字体环境、视口、DPR、语言、时区、Cookie 状态、测试数据种子和场景相位。

等待 `document.fonts.ready`、需要的图片解码与本地关键资产就绪。不要依赖 `networkidle` 等待一个有持续请求的站点永远安静；使用明确的可见就绪条件。

允许屏蔽的是无关动态内容，例如当前时间；不能屏蔽 Hero、卡片组、核心标题和正在拟合的产品展示。默认屏蔽面积不得超过截图面积的 **3%**，超出必须说明并重新选择状态。该比例是本项目的验证约束，不是行业通用标准。

重要：测试工具的 `animations: 'disabled'` 不会自动使任意 WebGL / GSAP 时钟进入正确参考姿态。主要动效必须通过可控输入或明确相位对齐，不能因为截图中一切静止就宣称动态一致。

### 14.3 本地测试桥

只在开发或验收构建中注入以下接口，生产构建不得暴露调试控制：

```ts
export interface CloneTestBridge {
  ready(): Promise<void>;
  seekCheckpoint(id: string): Promise<void>;
  setInput(input: {
    scrollYPx?: number;
    elapsedSec?: number;
    pointerNdc?: { x: number; y: number };
    reducedMotion?: boolean;
  }): Promise<void>;
  diagnostics(): {
    activeScenes: number;
    canvases: number;
    ownedListeners: number;
    textures: number;
    geometries: number;
    pendingAssets: number;
    layoutVersion: number;
  };
}
```

暴露名称为 `window.__FOLLOW_CLONE_TEST__`。`setInput` 接管本地运行时输入，不在组件内部偷偷增加第二个时间源。`seekCheckpoint` 使用 `design/checkpoints.json` 的定义，执行路由切换、就绪、章节定位和相位设置。

`ownedListeners` 是应用自行登记的监听器数量，不冒充浏览器所有监听器的真实总数。

原站没有这个桥。原站必须用合法浏览器操作与录屏定位相同的视觉状态，不能把只能在本地实现的调试调用写成原站采样步骤。

## 15. 验收门槛：有分数，更要有不可绕过的条件

### 15.1 先过硬门槛

以下任一项失败，不能宣布“高保真完成”：

- T00 的参考版本、路由范围、关键资产和截图可追溯；没有把作者案例当成完整当前录屏。
- 冻结范围内所有公开模板可访问，核心交互没有空按钮和死链。
- Hero 及曲面产品展示没有用整段视频、整页截图或不对应的通用 3D 物体替代。
- 主视觉中不存在明显替代素材、错误字形、缺失章节或未经记录的权限阻塞。
- 三个桌面视口通过适用的静态状态检查，十条动态轨迹都有可复查证据。
- `typecheck / lint / unit / e2e / build` 通过；无未处理异常、核心资产 404 或原站写请求。
- 下述 P0 / P1 问题清零；性能、资源清理、键盘操作及降级测试通过。

**P0：**页面不可用、泄露凭据、真实外部写请求、核心视觉缺失、测试证据伪造。  
**P1：**明显版式 / 字体错误、核心运动或交互错误、路由缺失、主素材替换、持续内存增长。  
**P2：**非核心局部偏移、次级动效节奏和装饰差异。  
**P3：**难以感知且不影响理解的微小差异。

### 15.2 建议的定量目标

下面是本项目的**拟定工程验收值**，不是原站已经达到的指标，也不是对工具精度的保证。

|维度|拟定目标|测量说明|
|---|---|---|
|关键静态锚点|主视口绝对偏差 ≤ 3 CSS px|使用锁定的 DOM 文字框、区块角点、图像边界；各状态至少 8 个有效锚点；三维轮廓另测|
|大标题文字框|宽高相对误差分别 ≤ 1%|行数、换行位置和主要字形还需独立人工判断|
|静态核心 ROI 像素差|差异像素占比 ≤ 5%|同环境、DPR 1；合成到同一背景后，RGB 任一通道归一化绝对差 > 0.1 记为差异像素；排除已批准小范围动态内容|
|核心三维轮廓|指定边缘标记偏移 ≤ 视口宽度的 1%|每个关键角度分别检查，不只计算平均值|
|滚动触发边界|对应章节有效行程误差 ≤ 2%|按章节实际滚动像素归一化，不按全页长度|
|离散动画时长|相对误差 ≤ 10%，容差下限为 2 个参考视频帧|关键起止状态必须一致，不能靠缓动掩盖缺失状态|
|连续循环周期|相对误差 ≤ 5%|至少比较一个完整周期；无完整参考则标记未验证|
|颜色|主要纯色区域 RGB 每通道中位绝对差 ≤ 4/255|同一颜色管理链路；不用于照片或抗锯齿边缘|

像素差是定位工具，不是唯一裁判。错误字体即便恰好占屏面积很小，也不能因总像素分数通过而忽略；不同硬件抗锯齿产生的微差也不能误当成几何错误。

目标有证据证明不适用时，可提交明确的阈值修订和原因，但不能为了让当前实现通过而临时放宽，也不能删除失败区域。

## 16. 性能、可访问性与工程稳定性

### 16.1 性能预算与测量条件

先记录测试设备、浏览器版本、GPU / 渲染模式、视口、DPR、是否录屏和电源状态。软件渲染环境的帧率不能冒充真实桌面 GPU 表现。

建议目标：主视口 DPR 1、资源预热后，运行 40 秒包含核心滚动和三维场景的脚本，独立运行 3 次，报告每次及中位结果。关闭录屏做性能采样；录屏另跑，不能混用结果。

- 正常硬件环境下以接近 60 fps 为目标，帧间隔 p95 ≤ 20 ms、p99 ≤ 32 ms。
- 冷启动实验室目标：LCP ≤ 2.5 秒、CLS ≤ 0.1，并注明实际网络和 CPU 限速条件；这些是测试目标，不代表真实用户现场指标。
- 初始关键资源传输量暂设 6 MB 软预算，纹理 GPU 占用估算暂设 128 MB 软预算；超出时用证据解释，不为硬压数字而把主要纹理降到明显模糊。
- 主线程不要每帧执行全站布局测量、字符串生成或 Vue 大范围响应式更新。

未测量就填 `NOT_MEASURED`。不要从一次流畅肉眼观察写出“稳定 60 fps”。

### 16.2 清晰度与资源策略

首屏优先加载必要字体、品牌资产、少量关键卡片与场景代码。长页下方的产品纹理和媒体按接近视口加载，进入前应有足够预热时间。

纹理内存估算可用 `width × height × 4` 字节，再按是否有完整 mipmap 链乘约 `4/3`；它只是常见未压缩 RGBA 的近似值，不适用于所有压缩格式。分别报告估算字节与 renderer 记录的纹理数量，不能把数量当字节。

根据卡片最大屏幕投影尺寸确定纹理档位。DPR 可以设上限并按硬件调整，但高分辨率屏幕的字体和图像清晰度必须检查，不能靠全局低 DPR 获得虚假的性能优势。

### 16.3 资源与生命周期

显式释放不再使用的 geometry、material、texture 和 renderer 相关资源；共享纹理由引用计数管理。Three.js 的资源不会因为对象从场景删除就全部自动释放，官方清理说明应作为实现依据。[S14]

反复进行二十次路由往返，记录第 1、5、10、20 次的 Canvas、场景、应用监听器、几何和纹理数量。合理缓存可以在初期上升后稳定，但不得单调无界增长。

页面隐藏时停止无意义动画；恢复时避免把隐藏期间的大 `deltaSec` 一次性推进造成闪跳。测试桥的确定性时间控制与此行为分开。

### 16.4 可访问性与失败恢复

- 导航、按钮、价格选项、FAQ 和表单均可键盘操作，有可见 focus。
- FAQ 状态使用正确的展开关系与属性，展开内容不被错误地永久隐藏。
- 弹窗存在时管理焦点并可通过实际参考支持的方式退出。
- 装饰 Canvas 不重复朗读文本；必要内容保留 DOM 等价物。
- reduced motion 下取消非必要持续旋转与大幅位移，保留内容和明确状态。
- WebGL 初始化失败或 context lost 时保留可读静态替代，不出现无限转圈加载。
- 演示环境不请求相机、通讯录或其他与复刻无关的权限。

这些是复刻工程的可用性约束；不声称原站已经具有完全相同的实现。

## 18. 持续迭代机制：不是一次生成，也不是无限乱改

### 18.1 四个质量层次

```text
L0 可观察：版本、页面、素材和关键状态有证据
L1 可运行：全站结构与演示交互完整
L2 可比较：三维、排版和动效都有可重复的采样
L3 高保真：主要差异达标，功能、性能和边界全部验证
```

不能从 L1 直接宣布 L3。三维“能转”、按钮“能点”和首页“能打开”属于实现进度，不属于最终质量证明。

### 18.2 每轮固定流程

```text
读取上轮状态与当前最小上下文
→ 复现问题，确认不是参考版本或测试相位变化
→ 挑选最重要的三个差异
→ 写出每个差异的原因假设及检验方法
→ 每个差异只修改必要变量
→ 跑针对性测试和相邻状态回归
→ 生成新对照与实际测量
→ 有改善则保留；退步则恢复本轮相关改动
→ 更新 backlog、scorecard、progress 和证据链接
```

禁止先写“优化完成”，再补截图。顺序必须是证据产生在结论之前。

### 18.3 差异优先级

先处理 P0 / P1；同级问题可用下面的排序启发式：

```text
priority = severity × visualSalience × affectedCoverage / estimatedEffort
```

分数仅用于安排工作，不是科学测量。字体错误、Hero 结构错误、整章高度错误等大影响问题，通常先于小图标的两个像素偏差；但不能因为某个难题修起来贵，就永远将其后移。

修复次序默认：

```text
错误版本 / 缺失资产
→ 页面网格 / 字体
→ 三维轮廓 / 透视
→ 滚动触发 / 动态相位
→ 功能状态
→ 装饰 / 细微颜色
```

### 18.4 三轮无改善时必须改变方法

同一缺陷连续三轮没有可复查改善，不继续随机调参。回到以下诊断问题：

- 是否用错了当前版与历史版？
- 是否字体或纹理本身不同，导致布局调整永远无法匹配？
- 是否把相机错误当作卡片半径错误？
- 是否参考和本地的滚动位置或时间相位没有对齐？
- 是否多层平滑造成动态延迟？
- 是否布局测量使用了错误的 DPR 或过期坐标？
- 是否所谓的模型实际上是曲面截图，或反之？

每一阶段最多进行 **6 轮连续的局部调参**。达到这个上限后必须切换到证据补采、原因重判或架构修正，而不是宣布完成。环境的真实执行预算由 Codex 和用户设置决定，本文件不虚构任何预算命令参数。[S10]

预算或工具限制终止本次执行时，提交当前最佳版本和恢复入口；`PARTIAL / BLOCKED` 不得改成 `COMPLETE`。恢复后从未完成项继续，不重新生成整个网站。

### 18.5 保留最佳版本，禁止质量倒退

每轮记录父版本、改动文件、关键参数、改前改后指标和证据路径。只保留经过验证的改善；某次修改局部变好但破坏其他视口时，不能以平均分略升为由覆盖稳定版本。

使用小范围提交或 patch 回退。不能执行 `git reset --hard` 清除用户工作，不把 unrelated changes 混进“恢复最佳版本”。

### 18.6 建议的状态文件

`quality/backlog.json` 每个条目至少包含：

```json
{
  "id": "DIFF-001",
  "stateId": "V02",
  "viewport": "1440x900@1",
  "severity": "P1",
  "category": "geometry",
  "status": "open",
  "referenceEvidence": "由实际采样文件填入",
  "localEvidence": "由实际截图文件填入",
  "observation": "写明可见差异，不填泛泛描述",
  "hypothesis": "写明本轮检验的单一原因",
  "nextAction": "写明文件、参数或测量动作",
  "attempts": 0,
  "ownerTask": "T05"
}
```

以上是 schema 示范，不可把示范文本原样当作完成的证据记录。验证脚本应拒绝这类占位内容出现在交付数据中。

`progress.md` 每轮保持短小：

```text
参考版本 / 当前构建 / 当前最佳构建
阶段与任务状态
本轮实际通过的检查
尚未满足的硬门槛
下一轮三个动作
阻塞、已尝试路径与恢复条件
最新截图、录屏和报告位置
```

`quality/scorecard.json` 记录各类别原始检查结果、内部评审分数、证据和未验证项。没有数据就写 `null` 与原因，不写猜测值。

### 18.7 上下文与并行纪律

资产清单稳定后，不每轮重新下载或搜索；参考版本冻结后，不每轮抓取线上新版本。若目标站变更，单独记录观察，不悄悄更换基线。

可并行的工作：已确定接口后的独立文本页面、fixture、单元测试和素材元数据。不能并行让多个代理修改同一个滚动运行时、全局字体或相机配置。

只有实际存在子代理工具时才使用。任务移交时附接口、参考状态、允许改动文件和验收命令，不复制整仓库与全部历史对话。

## 19. 明确禁止的低质量捷径

|捷径|为什么不能接受|应当怎么做|
|---|---|---|
|只做 Hero 就称“完整克隆”|忽略全站与长滚动体验|对照 route-map 与章节清单逐项完成|
|使用不匹配的艺术照或通用头像|主要像素结构和品牌内容不同|取得授权资产或明确报告素材阻塞|
|给所有元素加同一种淡入|没有重建具体的交互语言|逐个拆分并测量真实动效|
|把空间名片换成玻璃球、粒子、雕像|题材相近不等于设计相同|拟合真实几何轮廓和纹理|
|把曲面展示当作平面 `rotateY`|缺少真实弯曲与投影关系|用可控网格并做多角度比较|
|凭空写出原站 GLB 路径或依赖版本|使后续执行建立在假资源上|只引用真实请求证据|
|每个 section 都设置几百 vh 的 pin|改变阅读节奏与滚动距离|依据章节边界测量锁定区间|
