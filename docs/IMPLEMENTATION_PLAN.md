## 固定业务规则

活动绑定架构版本；quantity 在1..限购范围内。一个用户在同一活动同一商品只能创建一个订单，关闭归还库存但不恢复资格。幂等识别在售罄/时窗拒绝前完成，改变请求负载返回409。

数据库库存、请求、订单、Outbox在事务边界内提交；Redis投影和释放按状态版本幂等。支付与取消加行锁。已受理事件在活动结束后仍处理；活跃库存丢失时失败关闭，预热不能重置真实库存。所有数据库会话使用UTC，页面按本地时间展示。

## 实测结论与限制

- 功能正确性：后端15项、网关3项、前端7项通过，57项真实API通过，7项全库违规数量均0。
- V3持续负载：2000配置用户、峰值在途128，1092.95 HTTP QPS、P95 31.064ms；1000件库存最终1000订单。
- V3统一释放2000请求：峰值在途2000、800次429、HTTP P95 1694.257ms。突发延迟目标未达，不能写成全场景性能达标。
- HTTP吞吐包含业务拒绝，订单TPS另计。单机短测不是生产容量承诺。
- V4高级故障/Stream实验及崩溃脚本、Compose环境、多机高可用和长时间资源曲线：未纳入本轮完成声明。

详细证据与复现命令见 [VALIDATION.md](VALIDATION.md)。尚未实测的边界是明确保留的限制，不能用已通过的窄范围检查替代。
